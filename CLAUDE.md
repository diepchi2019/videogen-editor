# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A chat-driven, CapCut-style short-video editor: a browser timeline UI, Claude tool-use editing (in-app chat or via MCP from Claude Code), and real MP4 export through ffmpeg. Plain Node ESM (`"type": "module"`), no build step, no TypeScript, no linter configured. Requires Node 20+ and `ffmpeg`/`ffprobe` on PATH.

## Commands

```bash
npm install
npm start                 # editor at http://localhost:3000 (PORT to override)
npm run mcp               # MCP stdio server; forwards to a running editor (VIDEOGEN_URL, default http://localhost:3000)
npm test                  # unit tests (test/unit.test.js) then the end-to-end smoke test (test/smoke.js)
npm run test:unit         # unit tests only: pure model/ASS/graph checks, no ffmpeg needed (except one graph test that reads fonts)
```

- `test/unit.test.js` (node:test) covers ops, validation, settings precedence/secrets, moment scoring for shorts, TTS voice picking, masks/voice effects/stickers/smooth slow motion, the preview math in `public/preview.js`, font faces/metrics, transcript-to-timeline mapping, caption grouping, ASS output, batch/projects in the store, styles and templates (model + on-disk storage + tools), speed-ramp/reverse/freeze timing, ripple delete, groups and copies, LUTs, and the shape of the ffmpeg graph. It sets `VIDEOGEN_DATA` to a temp dir before importing the store.
- `test/smoke.js` spawns `server.js` on port 3999 with `VIDEOGEN_DATA` set to a temp dir, uploads `test/fixtures/*`, drives edits through `POST /api/tool/:name`, transcribes `speech.mp3` (skipped if there is no whisper model), speaks a voiceover with Piper and checks Whisper hears the same words (skipped without Piper), drives the ElevenLabs engine against `test/mock-elevenlabs.js` (key checks, key never sent back, settings in the request, no repeat request), exports with `wait`, checks the output with `ffprobe`, switches projects, and drives `mcp.js` with a real MCP client. It needs real ffmpeg. It writes `test/last-frame.png` and `test/last-timeline/*.jpg` (gitignored) — look at them after visual changes.
- `test/mock-claude.js` is a fake Anthropic Messages API (port `MOCK_PORT`, default 3200) for exercising the chat loop without a key. Start it, then run the server with `ANTHROPIC_API_KEY=x ANTHROPIC_BASE_URL=http://localhost:3200` and post to `/api/chat`.

Settings: `src/settings.js` is the one place configuration is read (`get(key)`: environment variable > `data/settings.json` > default; `SETTINGS` lists every key with its env var, label and check). The ⚙ Settings dialog edits it through `GET/POST /api/settings` (a new Anthropic or ElevenLabs key is checked first; secrets are write-only, `publicSettings()` gives only `set`/`hint`; never add a tool that takes a key). `onSettingsChange` lets modules drop caches (Piper command, default font, ElevenLabs cache); the file is re-read when it changes on disk; the old `data/tts.json` is merged in once. To add a setting: add it to `SETTINGS`, read it with `get()`, and list it in `SETTING_GROUPS` in app.js. Environment variables (each maps to a setting unless noted): `ANTHROPIC_API_KEY` (enables the in-app chat), `CLAUDE_MODEL` (default `claude-sonnet-5-5`), `VIDEOGEN_DATA` (data dir, default `./data`), `VIDEOGEN_FONT` (default text font: a family name or a font file path; otherwise the first installed of Arial, DejaVu Sans, Helvetica, Liberation Sans, Noto Sans), `ELEVENLABS_API_KEY` (ElevenLabs text to speech), `VIDEOGEN_PIPER` (piper executable for text to speech; default `python -m piper` from `pip install piper-tts`, voices in `models/piper/`), `VIDEOGEN_WHISPER_MODEL` (whisper.cpp ggml model file; otherwise `modelPath()` in `src/transcribe.js` picks the most accurate of `MODEL_FILES` found in `models/` or `data/models/`: large-v3-turbo-q5_0, large-v3-turbo, small, base, tiny; gitignored, download from huggingface.co/ggerganov/whisper.cpp; `/api/state` reports it as `whisperModel`; `use_gpu` is on by default and the gyan.dev ffmpeg build uses the T550: 55s of speech takes 9s on GPU vs 51s on CPU with turbo), `PORT` and `VIDEOGEN_DATA` (environment only: needed before the settings file can be read), `VIDEOGEN_URL` (MCP only), `ANTHROPIC_BASE_URL` / `ELEVENLABS_BASE_URL` (environment only; tests point them at the mocks).

ffmpeg must be built with libass and (for captions) whisper. ffmpeg 7+ reads the filter graph with `-/filter_complex <file>`; `render.js` detects the version and falls back to `-filter_complex_script` on older builds.

## Architecture

**One edit pipeline, three callers.** Every timeline mutation is a pure function in `ops` in `src/model.js`, with signature `(draftProject, input) => message string`. It throws `OpError` on invalid input, and the error text goes back to Claude, so make it actionable. Edits from the browser UI, the in-app chat, and MCP all go through the same path:

```
UI (public/app.js) ─┐
chat (src/chat.js) ─┼─> executeTool (src/tools.js) ─> store.apply (src/store.js) ─> ops[name] (src/model.js)
MCP (mcp.js) ─HTTP─>┘   via POST /api/tool/:name
```

- `src/store.js` keeps the open project in memory. `apply()` runs the op on a `structuredClone` draft, pushes the previous project onto that project's undo stack (max 100, kept per project id), writes `data/projects/<id>/project.json` synchronously (tmp + rename), and emits change events. Undo and redo swap whole project snapshots. `applyBatch()` (tool `batch_edit`) runs many ops on one draft as one undo step; a string `"$N"` in a later step's input is replaced by the id created by step N. Projects: `listProjects/createProject/openProject/duplicateProject/deleteProject` (delete moves the folder to `data/trash`). `migrate()` in model.js upgrades any loaded project; a legacy `data/project.json` is moved into `data/projects/` on first start.
- `server.js` sends every store change to the browser over SSE (`GET /api/events`, events `project`, `jobs` and `chat-action`). That is how edits made by Claude show up live in the UI. The `x-source` header (`ui`/`mcp`/`claude`) labels where a change came from.
- `src/tools.js` defines `TOOLS` once, in Anthropic `input_schema` format. The chat sends them to the API as they are, and `mcp.js` fetches them from `GET /api/tools` and maps them to MCP `inputSchema`. **To add an editing tool:** add the op to `ops` in `model.js` and its schema to `TOOLS`. The `default:` branch of `executeTool` routes it to `store.apply`. Tools that aren't ops (`get_timeline`, `look_at_*`, `batch_edit`, project tools, `list_fonts`, `transcribe_asset`/`get_transcript`/`add_captions`, `analyze_audio`/`mark_beats`, `find_moments`/`make_short`, `add_voiceover`/`list_voices`, `create_proxies`, style/template tools except `apply_style`, `undo`/`redo`, `export_*`) are special-cased in the `switch`; async work (whisper, rendering) lives there, never in ops. `set_captions` is an op without a schema: `add_captions` transcribes, maps words with `timelineWords()`, then applies it. `toolAnnotations()` adds MCP hints (`/api/tools` includes them; the chat sends plain `TOOLS` because the Anthropic API rejects unknown fields). `import_media` exists only in `mcp.js` (it reads local paths and uploads them; `.ttf/.otf` uploads go to `data/fonts`). `mcp.js` also serves resources `videogen://project/timeline` and `videogen://project/json`, and prompts `make_reel`, `reel_from_template`, `save_my_style`, `reframe_to_vertical` and `shorts_from_video` (`PROMPTS` in mcp.js).
- **Styles and templates** (`src/presets.js` stores them in `data/styles/<id>.json` / `data/templates/<id>.json`, shared by all projects; same name = update in place; delete moves to `data/trash`). A style (`normalizeStyle` in model.js) has optional sections `canvas`, `clips` (fit, transition, animIn/Out, color, imageMotion), `title` (text style fields incl. default x/y), `captions`, `music` (volume, fades, duck), and `intro`/`outro` `{asset, clip}` / `logo` `{asset, overlay}` that carry the full asset record (`ensureAsset` re-adds it by `file`). `BUILTIN_STYLES` in model.js are always listed and read-only. `apply_style` is an op: it gets the style through `env.loadStyle` (set in tools.js, like `env.resolveFont`), tags the items it inserts with `styleRole` intro/outro/logo (re-apply replaces them), keeps text positions, and writes `p.style = {id, name, clips, title, captions, music}`. `add_clip`, `add_text`, `set_captions` (first captions) and `add_music` (role music) use `p.style` as defaults, and `add_clip` inserts before a style outro. `save_style` captures with `styleFromProject` and merges explicit sections over it. Templates: `makeTemplate(p)` turns main-track clips into slots (`slot`, `slotDuration`, `assetId: null`, regions dropped) and keeps only the assets that texts/overlays/music still use. `fillTemplate(p, tpl, input)` puts media into the slots (keeping length; a video is shifted earlier when the source is too short) and is run by `create_from_template` through `store.createProject({build})`, so a failed fill creates nothing.
- Uploads (`POST /api/upload`): `.ttf/.otf` go to `data/fonts`, `.cube` to `data/luts` (`importLut` checks for `LUT_3D_SIZE`), and audio-only `.webm` (browser voiceover recordings, which have no duration) is converted to `.m4a` before probing. The UI records with MediaRecorder and adds the take with `add_music role voice`.
- `look_at_asset` (source frames, `src/media.js` `extractFrames`) and `look_at_timeline` (composited output frames, `render.js` `renderFrames`, which runs `buildCommand` in frames mode with a `select` filter) return Anthropic image content blocks. `mcp.js` turns them into MCP image blocks.

**Timeline model.** There is one ordered main video track, `project.clips`. Clips have no stored start time. `layout(p)` works out the positions, and a transition on clip *i* overlaps it with clip *i-1* by the transition's duration, so adding transitions makes the video shorter. Clip `in`/`out` are seconds in the source file. Text, overlay and audio `start`/`end` are seconds on the timeline. Clip duration comes from `src/timing.js` (`clipLength`; `clipDuration` in model.js): `(out - in) / speed`, or the exact integral of 1/speed for a speed ramp. Clip timing fields:
- `ramp: {preset?, points:[{at, speed}]}` (`set_speed_ramp`, presets `RAMP_PRESETS` in timing.js): `at` is a 0-1 fraction of the played source range and speed changes linearly between points, so a trim stretches the ramp and `avgRate(c)` (source s per timeline s) stays constant. While a ramp is set, `speed` is 1 and ignored; `set_clip speed` removes the ramp. `split_clip` divides the points with `subRamp`.
- `reverse: true` plays out..in (`playedAt`/`srcAt`/`localAt` handle the direction; a split's first half is the later source). Limited to `REVERSE_MAX` (10s) of source because ffmpeg's `reverse` buffers every frame.
- `freeze: true` (`freeze_frame`) holds source `in` for `out - in` seconds (speed 1, silent; `out` may pass the end of the file).
- `smooth: 'blend'|'motion'` (`set_clip smoothSlowMo`) adds `minterpolate` after `setpts`, only when the clip is slowed (speed < 1 or a ramp point < 1). `motion` (mci) first caps the frame at the canvas size and is slow (about 7s per source second at 720p).
- Never compute source/timeline time with `speed` directly: use `srcAt`, `localAt`, `speedAt`, `avgRate` from timing.js. The browser imports the same file from `/lib/timing.js`.
Other layers:
- `overlays[]`: video/image placed at an absolute `start` on top of the main track (not magnetic), with `track` (z-order), `fit` (free = `x`,`y` center + `scale` as width fraction; cover; contain), `opacity`, `rotate`, `crop`, flips, `volume`, `animation`, `blend` (`BLEND_MODES`; normal = no field) and `key` `{color, similarity, blend, despill}` (chroma key, tool param `chromaKey` green/blue/hex/none; despill follows the key color via `spillOf`). `mask` `{shape: circle|rect|linear|mirror, x, y, w?, h?, angle?, feather, round?, invert?}` (`set_mask`, overlays only) is in fractions of the overlay's own frame; linear keeps the side below a line through x,y (angle 90 = left, -90 = right, 180 = above), mirror keeps a band of height h. `loop: true` repeats a video overlay (`-stream_loop -1`; `out` may pass the file end and source time wraps to 0); animated GIFs probe as `video` with `codec: 'gif'` and loop by default (stickers). `animation` `pop` grows a free-fit overlay in with an overshoot. Clips, overlays and audio items can have `denoise` 0-1 (`afftdn` at 6-30 dB, before tempo changes), `voice` (`VOICE_EFFECTS`, ffmpeg chains in `VOICE_FX` in render.js) and `pitch` in semitones (`asetrate` + `atempo`, length kept); `soundFilters()` applies them in that order.
- Clip `transform` (`crop` fractions, `rotate`, `flipH/V`, `scale`, `x`, `y`; omitted keys = identity) and `motion` (`{preset, intensity}` Ken Burns).
- Clip `reframe` `{easing, zoom?, points:[{at, x, y}]}` (`reframe_clip`, auto reframe): the subject center as fractions of the source frame at SOURCE seconds `at`, so it survives trim/split/speed (split halves keep all points; `replace_clip_asset` and templates drop it). Only active with fit cover (the op sets it). `reframeTrack(c, axis)` in timing.js turns it into a clip-local keyframe track; render replaces the centered cover crop with `crop` x/y expressions clamped to the frame (`zoom` scales the cover fit up first); the preview uses `coverPosition` for CSS `object-position` (plus scale/translate for zoom). `look_at_asset {grid: true}` draws a 10% grid so Claude can read positions.
- Clip `regions[]` (tools `remove_region`/`delete_region`): hide burned-in text/logos. `{id, x, y, w, h}` are fractions of the SOURCE frame and `from`/`to` are SOURCE seconds, so they survive trim/split/speed (split halves share region ids; `delete_region` removes from all). `mode` `fill` = `delogo`; `patch` = copy the box from the clean frame at `patchAt` with a `feather`ed alpha edge (one extra `-ss patchAt -t 0.5` input per patch). Applied first in the clip chain, before speed and transforms. `replace_clip_asset` swaps `assetId` and keeps every other clip field.
- `color` on clips and overlays (`set_color`): `brightness`, `contrast`, `saturation`, `temperature`, `vignette` (defaults are omitted) plus a look `filter` (`FILTERS`) and `filterIntensity`, and an imported `.cube` `lut` with `lutIntensity` (resolved through `env.resolveLut`, stored in `data/luts` by `src/luts.js`; render uses `lut3d` before the look; no preview). render.js `LOOKS` maps looks to ffmpeg filters (a look below intensity 1 is `blend`ed over the original); `LOOK_CSS` in app.js is the preview approximation, keep both in sync.
- Clip `animIn`/`animOut` `{type, duration}` (`CLIP_ANIMS`, set via `set_clip`) and `effects[]` `{id, type, from, to, intensity, rate?}` (`add_effect`). `keyframes` on clips and overlays: `{prop: {easing, points:[{t, v}]}}` (`set_keyframes`, props in `KEYFRAME_PROPS`). Effect and keyframe times are stored relative to the item's start (tools take timeline seconds), so `split_clip` divides them between the halves (`splitTimed`), and the first half keeps `animIn`, the second `animOut`.
- Texts, overlays, audio items and markers can share a `group` id (`group_items`); `move_items`, `duplicate_items` and `ungroup_items` take a whole group. `delete_range` is the ripple delete: it splits clips at both ends, removes what is inside from every layer, shifts later items left and shortens items that cross it (role music keeps playing). `findItem`/`withGroups` in model.js look items up by id across all layers.
- `markers[]` `{id, t, kind: beat|note, label?}` in timeline seconds. `mark_beats` analyses a music item and writes beat markers; `fit_clips_to_beats` trims clip out-points so each cut lands on every Nth beat (accounting for transition overlaps). Music items can have `duck` 0-1.
- `texts[]` carry style fields (`font`, `bold`, `outline`, `shadow`, `blur`, `box`, `animation`, `animationOut`, `style` preset name). A text without `outline` keeps the old automatic outline.
- `captions`: `{style, lines:[{id,start,end,words:[{w,start,end}]}]}` in timeline seconds. Transcripts are cached per media file in `data/analysis/<file>.words.json` (source seconds, `version` 2; older caches are redone) and mapped through clip in/out/speed by `timelineWords()`. `transcribe()` decodes 16 kHz mono in Node, cuts quiet runs of 0.8s or more (`speechRanges`, keeping a 0.2s pad), runs whisper on the shortened audio and maps words back (`mapWords`), because whisper stretches the first words of a chunk back over leading silence and invents words in long quiet parts. Words come back to back, so a word straddling a cut goes after the pause if the previous word ends a sentence, otherwise to the side holding most of it. ffmpeg's own `vad_model` option was tried and is not used: it only picks chunk split points, was 7x slower and still gave early times and made-up words.
- `music[]` is every audio item: `role` music/sfx/voice and `track` (the tool names stay `add_music`/`update_music`/`delete_music`).
Colors are validated to hex by `color()` because they go into filter graphs and ASS files. `summarize(p)` produces the text view Claude sees (in `get_timeline` and in the chat system prompt), so keep it in sync when you add fields.

**Rendering.** `src/render.js` `buildCommand` turns the project into one ffmpeg invocation. Each clip becomes an input (a freeze frame reads 0.5s and holds its first frame with `tpad`), normalised to WxH@fps with stereo 48k audio of exact length (silence is generated for clips without audio or images; fit modes are contain, cover and blur). The clips are chained with `xfade`/`acrossfade` using the overlaps from `layout`. Per clip: regions, timing (reverse after `fps` + a canvas-size cap; smooth slow motion; constant `setpts=PTS/speed` or a ramp as `setpts='(rampExpr)/TB'`, the closed-form time curve; ramp audio is cut into constant-tempo `atempo` segments by `rampAudioSegments` and concatenated, each exactly as long as its video), transforms, color (`applyColor`), fit, then scale/position (overlay on a color canvas; with keyframes or zoom/slide animations `clipPlacement` builds per-frame expressions for `scale eval=frame` + `overlay`), then Ken Burns (`zoompan` on a 2x frame), then the tail (exact duration at fps), then fade animations and effects (`applyEffect`, all size- and length-preserving with clip-local `t`) and `settb=AVTB` (xfade needs equal timebases). Keyframes become nested `if/clip` expressions (`kfExpr`). Gotchas: wrap expressions in parentheses before multiplying (`W*(expr)`); filters that keep per-frame buffers (`geq`, fixed-box `rotate`) must run before a per-frame `scale` (geq crashed ffmpeg 9 when frame size changed), so overlay alpha and rotation come first; a filter with no options takes `name=enable=...`, not `name:enable`. Ducking: clip audio and voice items are `asplit` into a sidechain key for `sidechaincompress` on each music item with `duck`. Export options (`export_video`): `resolution` (short side), `fps`, `bitrate`, `encoder` cpu/gpu/auto (`detectGpuEncoder` test-encodes NVENC, Quick Sync, AMF once). Overlays are chained with `overlay` (`setpts=PTS+start/TB`, `enable=between`), and their audio joins the mix. A chroma key (`chromakey` + `despill`) runs first in the overlay chain, before alpha and scaling. A mask comes next: `maskExpr` (a signed distance softened over the feather) is drawn with `geq` once on the first frame's alpha, repeated with `loop`, `blend` multiplied into the alpha and put back with `alphamerge` (12x faster than a per-frame `geq`). Effects without timeline support (pixelate, mirror, kaleidoscope, comic) process a `split` copy and are `overlay`ed back with `enable`. An overlay with a blend mode is placed on a transparent full-canvas layer, blended with the frame below in `gbrap` (the `blend` filter needs equal sizes and ignores alpha), and the layer's `alphaextract` is used as the mask (`alphamerge` + `overlay`). All texts and captions are one ASS file built by `src/ass.js` (PlayRes = canvas size, so sizes are canvas px) and drawn with the `ass` filter; `src/fonts.js` reads family names from font files and copies the needed families into the render's `fontsdir`. Escape filter option values with the `q()` helper. Audio items are mixed with `amix`. Jobs (`src/jobs.js`) run asynchronously in an in-memory map and are polled through `/api/jobs/:id` / `export_status`, or awaited with `export_video {wait:true}`. A `draft` export renders at half resolution. `export_cover` renders one frame with `renderFrames(p, [t], {still: true})` (full size, `-q:v 2`) into `data/exports`. The browser preview approximates transitions, color/looks, clip scale/position/rotate/flip, clip in/out animations and overlay keyframes with CSS (`transitionCss`, `colorCss`, `clipAnim`, `kfVal` in app.js), plays speed ramps by changing `playbackRate`, and shows freeze frames and reversed clips by seeking (no sound). Overlay masks preview with CSS `mask-image` gradients (`maskCss`), pop with a CSS scale (`popScale`), and GIF overlays play as `<img>` from `/media/` (the browser animates them and keeps transparency). Overlay blend modes preview with CSS `mix-blend-mode` (`BLEND_CSS`; `#overlays` must not get a z-index or the blend stops at that stacking context). `public/preview.js` (pure, unit-tested) mirrors the rest of render.js/ass.js: `kenBurns`/`zoomAbout` (motionFilter as a scale about the view-window anchor), `cropBox` (crop as CSS `object-view-box`), `vignetteCss` (cos^4 falloff), `effectsAt` (every effect as a transform, CSS filter, SVG filter `#vg-rgb-N`/`#vg-comic-N`, light-leak/grain layer, or a canvas effect: pixelate, mirror and kaleidoscope repaint the clip frame on a canvas with `paintClipFrame` + `drawEffect`), and `textLook`/`textAnim` (ASS text: stroke under the fill = 2x the border, shadow, glow, box, all in/out animations and typewriter). Each `.layer` holds an `.inner` wrapper that carries Ken Burns and effects for the whole clip, while the layer itself carries the transition. Texts use the export's fonts: `GET /api/font/:family?face=regular|bold|italic|bolditalic` (`fontFile` guesses faces from file names) and `?metrics` (`emRatio`: libass sizes ascent+descent, CSS sizes the em; also lists the faces); `/api/state` has `defaultFont`. Keep preview.js in sync when render.js or ass.js change. Not in the preview: LUTs, chroma key, removed regions, audio processing (noise reduction, voice effects, ducking) and smooth slow motion; use `look_at_timeline` or a draft export to see them.

**Long video to shorts** (`src/moments.js`). `find_moments` gathers local signals only (the whisper transcript, a loudness curve from `loudness()` cached as `data/analysis/<file>.energy.json`, shot changes from ffmpeg's scene score in `sceneChanges()` cached as `.scenes.json`) and `findMoments()` (pure, unit-tested) scores every window of whole sentences between minDuration and maxDuration: continuous lively speech, loudness peaks, a hook/question opening, clean edges, shot changes, length near the target, and `query` words (a match outranks everything else). It returns the best non-overlapping windows with in/out snapped just outside the words; without speech it cuts on shot changes. `cleanWords` drops whisper repeats collapsed onto one instant. Choosing by meaning is Claude's job: it reads the excerpts. `make_short` builds a new project with `store.createProject({build, open})` (`open: false` saves without switching): one clip, 9:16, fit cover, optional `apply_style` and title, captions via `timelineWords` + `set_captions`. The UI shows a ✂ button on videos of 20s+ that lists the moments in the chat panel with a "Make short" button each.

**Text to speech** (`src/tts.js`). Engines `piper` (local) and `elevenlabs` (API); `synthesize({engine, ...})` picks the saved default (`ttsSettings().engine`) when none is given. Its settings (`tts.engine`, `tts.elevenlabs.apiKey/model/voice`, `tts.piperCommand`) are in `src/settings.js`; the Voice panel saves engine/model/voice through `POST /api/tts` and sends you to ⚙ Settings for the key. The key is write-only: `ttsSettings()` returns only `hasKey`/`keySource`/`keyHint` (last 4), and no tool takes a key (keys must not pass through Claude). `GET /api/tts?voices` adds the account's voices and TTS models (with a Vietnamese flag). ElevenLabs: `POST /v1/text-to-speech/{voice}` (mp3), base URL `ELEVENLABS_BASE_URL` (tests use `test/mock-elevenlabs.js`, which accepts keys starting `test-`), default model `eleven_v3` (stability only 0/0.5/1, 5000 characters max, audio tags like [excited]); `elevenVoiceSettings`/`piperNoise` map expressiveness 0-1 to each engine; speed is applied afterwards with `atempo`. Cached files are keyed by engine + text + voice + model + settings, so repeats cost nothing. OpenAI TTS is deliberately not offered (its speech-endpoint models shut down 2027-01-06). Piper runs as a command (`piperCommand()`: `VIDEOGEN_PIPER`, else `piper` on PATH, else `python -m piper`, probed once) with `PYTHONUTF8=1` and the text in a UTF-8 file (Windows stdin would mangle Vietnamese). Voices are `*.onnx` + `.onnx.json` in `models/piper/` or `data/models/piper/` (`listVoices`); `pickVoice` takes an id or language code, else guesses vi/en from the letters. `synthesize` writes `data/media/f_tts_<hash>.wav`, keyed by text + voice + speed + speaker + pause, so a repeat is instant. `add_voiceover` adds the asset (with `tts: {voice, text}`) and an `add_music role voice` item, so ducking, voice effects and `add_captions` apply. `/api/state` lists `voices` for the 🗣 Voice panel. Lipsync would be a later step that takes any voice item.

**Audio analysis and proxies.** `src/audio.js` decodes with ffmpeg to mono float PCM: `waveform()` (peaks for `GET /api/waveform/:assetId`) and `analyzeAudio()` (loudness, silences, tempo by autocorrelation of a spectral-flux onset curve, beats by dynamic programming); both cached in `data/analysis/<file>.peaks.json` / `.audio.json` (bump `VERSION` when the analysis changes). `analyzeSamples` is pure and unit-tested on click tracks. Proxies (`src/media.js`): videos whose codec the browser can't play or larger than 1440p get a 720p H.264 copy in `data/proxies/` as a `proxy` job on import (`create_proxies` for old imports). The preview loads videos from `/preview/<file>`, which serves the proxy when it exists; exports always use the originals.

**Chat.** `src/chat.js` runs a manual tool-use loop (at most 15 steps) with history kept on the server (trimmed to about 30 messages, cut only at a plain user text turn). The current project summary is injected into the system prompt on every request.

**Frontend.** `public/` is vanilla JS/CSS served statically, with no framework and no bundler. `app.js` is an ES module (it imports `/lib/timing.js`). Selection is `picked` (id -> kind, Ctrl/Shift+click adds; clicking a grouped item picks its group) plus `sel` (the item in the inspector). Dragging snaps to the playhead, clip edges, markers, the I/O range and other items (`snapTargets`/`snapDelta`, toggle saved in localStorage); dragging one of several picked items calls `move_items`.

## Data

Everything lives in `data/` (gitignored): `projects/<id>/project.json`, `state.json` (open project id), `settings.json` (all settings incl. API keys, see `src/settings.js`; never sent to the browser), `media/` (uploads renamed to `f_<hex>.<ext>`, shared by all projects; each project has its own `assets` map), `thumbs/`, `exports/`, `analysis/` (transcripts, waveforms, audio analysis, loudness curves and shot changes for find_moments), `proxies/` (preview copies), `fonts/` (imported fonts), `luts/` (imported .cube LUTs), `styles/` and `templates/` (saved reel styles and templates), `trash/` (deleted projects), and temporary `tmp-*` render dirs.
